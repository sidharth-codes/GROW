# GROW Bugs, Risks, and Technical Debt

Severity describes potential impact; priority is the recommended order in [REMAINING_WORK.md](./REMAINING_WORK.md). “Risk” means not confirmed as an observed production failure.

| ID | Category | Type / severity | Evidence and reproduction | Impact | Recommended action | Priority |
|---|---|---|---|---|---|---|
| G-01 | ML / price forecasting | Confirmed defect — High | `app/backend/ml/price_model.py`: `run_walk_forward_cv` uses `mean_absolute_error` before a local import. Local synthetic month series reproduction raised `UnboundLocalError`. | Price assessment crashes once sufficient records reach a Ridge fold; market feature cannot complete. | Import metric at module/function start; add fixture test with enough records to enter a fold and assert finite metrics. | P1 |
| G-02 | API integration / ingestion | Confirmed wiring defect — High | `price_ingestion/fetcher.py` writes `data_gov_in_kerala_prices.json` and returns that path; `price_ingestion/pipeline.py` accepts it as `source_file` and then uses `csv.DictReader`. | Data.gov.in success cannot be reliably normalized by the CSV-only pipeline; may overwrite active price outputs with empty/header-only data after a seemingly successful fetch. | Parse API JSON records explicitly or convert them to a validated canonical CSV; reject unsupported input before writing active files. | P1 |
| G-03 | Data validation | Confirmed validation gap — High | `dataset_manager/validator.py`: duplicate primary keys append warnings, while `is_valid` depends only on errors. Float checks compare bounds but do not reject NaN/Infinity; integer values are converted with `int(float(value))`. | Duplicate observations can pass upload; non-finite costs can pass and later break JSON serialization/calculation; fractional integers can be silently truncated. | Reject duplicates where schema primary key requires uniqueness; require finite numeric values and exact integer semantics; test these cases. | P1 |
| G-04 | API errors | Confirmed inconsistency — Medium | `api.py` GET dispatcher maps missing data to 503 and absent records to 404. POST `/api/recommendations` catches only `ValueError`, not `RuntimeError` or `LookupError`. | Missing-dataset POST requests can terminate with unhandled server exception rather than a structured response. | Share one route error-mapping layer; add POST tests for missing/unknown profile and missing files. | P2 |
| G-05 | Profitability semantics | Confirmed limitation / calculation risk — High before enabling | `api.py` profitability joins most recent matching wholesale price and latest historical district yield, then computes revenue as kg/ha ÷ 100 × INR/quintal, subtracting listed total cost. Dates, harvest timing, quality/saleable fraction, price market aggregation, cost reference year and inflation are not aligned. No current cost/price records exist to test a populated scenario. | A numerically correct unit conversion could still be misleading as expected profit; results could mix non-comparable years and nominal rupees. | Keep blocked until data exist; define date/market selection, saleable output, total vs partial cost, gross/net and ROI definitions; add known-value and loss scenarios. | P1 |
| G-06 | Recommendation logic | Confirmed behavioral limitation — Medium | `api.py` recommendation code selects the maximum score per crop across all matching soil profiles when no soil type is selected. | The district-level list can show the most favorable soil for each crop, hiding poorer matching profiles and overstating general district fit. | Display profile-level rows or clearly aggregate/label best-case selection; include score-rule explanation. | P2 |
| G-07 | Suitability quality | Confirmed method limitation — Medium | `notebooks/07_recommendation_model.ipynb` uses substring/token overlap for texture, exact match vs fixed partial score for drainage, and approximate qualitative-pH intervals. The stored 230-row output has 50 blank pH component values. | Score is an uncalibrated heuristic; “similar” and “different” classes may not reflect agronomic suitability; users could overinterpret ranking. | Keep heuristic label prominent, document rule basis, validate rules with agronomists and provide profile-level reasons. | P2 |
| G-08 | Soil clustering | Confirmed method limitation — Medium | `soil_clustering.py` ordinal-encodes nominal categories then applies Euclidean KMeans; only 23 records. | Arbitrary category order affects clusters and silhouette; unstable groups are not agronomic classes. | Evaluate one-hot/Gower or suitable mixed-data distance, stability and expert interpretation; retain low-confidence framing. | P2 |
| G-09 | Registry integrity | Confirmed design risk — Medium | `dataset_manager/registry.py` catches any exception loading JSON and then initializes and saves a new registry to the same path. Save writes JSON directly rather than atomically. | Corrupt registry can be overwritten, discarding prior source/validation metadata; interrupted writes can leave corrupt state. | Preserve/rename corrupt file with an explicit error; use validated schema and atomic replace plus backup. | P2 |
| G-10 | Concurrent writes | Confirmed design risk — Medium | `DatasetIngestionService.commit_upload` copies raw, processed, and root files in sequence and updates registry; no lock/temp-and-replace strategy. Weather/yield/price pipelines also write active files directly. | Concurrent uploads or process interruption may leave file copies and registry inconsistent; identical raw filename in a same-second upload can collide. | Use unique archive names, atomic staging/promotion and registry updates, and a per-dataset lock. | P2 |
| G-11 | Security / local server | Risk requiring threat-model confirmation — Medium | `api.py` binds `127.0.0.1` (reduces network exposure), but mutating upload route has no authentication, CSRF token or Origin validation and accepts up to 50 MB. | Browser-based cross-origin requests or untrusted local users may alter datasets when the service is running. Not suitable for deployment as-is. | Keep explicitly local-only, add Origin/CSRF checks and authentication before network exposure; test security controls without destructive payloads. | P1 before exposure |
| G-12 | Security / serialized models | Risk — Medium | API `joblib.load`s local model artifacts for prediction. Joblib/pickle artifacts are executable during deserialization if an attacker can replace them. | Compromised writable model directory could execute code in server process. No upload route accepts model files, so this depends on local artifact tampering. | Restrict artifact write permissions, verify trusted checksums/signatures or use safer model formats where practical. | P2 |
| G-13 | Source retrieval | Unverified integration risk — Medium | NASA POWER and Data.gov.in callers exist, but this audit did not issue external requests. Data.gov.in requires a key passed as a CLI option; no environment-variable example or key rotation guidance was found. | External access, current endpoint behavior, rate limits, and real ingestion are not proven. | Mock-test request formatting and run authorized small live smoke test separately; avoid command-line secrets and redact credentials. | P2 |
| G-14 | Data quality / soil | Confirmed coverage gap — Medium | Soil file has 23 qualitative records across 13 districts; 14th district has no soil record. No quantitative soil laboratory dataset exists. | Recommendation coverage does not include all districts or field-specific fertility/soil measurements. | Collect referenced district profiles and separate farm sample schema; fail clearly where missing. | P1 |
| G-15 | Data quality / yield | Confirmed limitation — Medium | Yield output has 6,422 records, 22 crops, all one `Annual` season label. | No seasonal yield analysis; annual average may hide crop-cycle differences. | Preserve source season/cycle definitions where available; document unsupported seasonal requests. | P2 |
| G-16 | Notebooks | Confirmed incomplete project artifacts — Low/Medium | Notebooks `02_data_cleaning` through `06_price_model` are each zero bytes; notebook JSON inspection fails at byte 0. | Planned analyses cannot be reviewed/reproduced from notebook files. | Recover from version history if desired or remove empty placeholders and document Python pipelines as canonical. | P2 |
| G-17 | Documentation | Confirmed mismatch — Low | README structure labels backend as FastAPI and frontend as React + Vite, while actual app is a Python standard-library server with static vanilla JS. | New developers may attempt nonexistent package/build commands or misunderstand runtime. | Correct architecture description and document tested setup. | P2 |
| G-18 | API request handling | Confirmed hardening gap — Low/Medium | POST parses `Content-Length` with `int()` outside a request-level guard; malformed lengths may cause unstructured handler failures. | Bad clients receive disconnects/log traces rather than a stable JSON error. | Validate headers and body size with structured errors; test malformed and empty bodies. | P2 |
| G-19 | Registry/dashboard semantics | Confirmed UX gap — Low | Dataset page omits schema/missing/date-range fields despite those being tracked; dashboard has one weather freshness date but no per-source age or collection event history. | Users may interpret file availability as current/comprehensive source coverage. | Show source timestamps, date span, validation/missing counts and ingestion activity. | P2 |
| G-20 | Deployment | Confirmed non-readiness — High if internet-facing | Single-process stdlib HTTP server, no auth/CSRF, no production deployment config, no logging/monitoring plan, no pinned dependencies. | Operational and security properties are insufficient for multi-user/network deployment. | Keep local prototype or define a separate production architecture with server, auth, observability, TLS and deployment tests. | P1 before deployment |
